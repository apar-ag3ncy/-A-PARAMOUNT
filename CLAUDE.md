# Paramount — project guide

Premium catalog site for **A Paramount Engineering Works** (Jain/Hindu temple artifacts, est. 1968). View-only, cinematic scroll. Planning docs live one level up: `../PARAMOUNT_BUILD_PLAN.md`, `../PARAMOUNT_CONTENT.md` (locked content + design tokens = source of truth), `../PARAMOUNT_SCROLL_UI_PROMPT.md` (animation layer).

## Conventions
- **Design tokens** live in `src/app/globals.css` `@theme` (Tailwind v4, CSS-first) — palette is olive-brass `#8A7F4A` on cream `#FEF4DA`. Edit tokens there, not in `tailwind.config.ts`. Utilities: `bg-cream`, `text-olive-deep`, `font-display` (Spectral), `font-serif` (Cormorant Garamond, use italic), `font-body` (Inter), `rounded-card`.
- **Every image renders through `AssetFrame`** (`src/components/ui/AssetFrame.tsx`). 30 of 50 products carry the client's real photos (`catalog.ts` `image` → `/public/products/*.webp`, shown UNCROPPED via `fit="contain"` — client mandate: never crop product shots). The rest show the empty frame until Sanity/`urlFor()` fills them.
  - ⚠️ **Known bug:** `AssetFrame` takes *two* image sources — `image` (Sanity) and `src` (the local `/public` photo). Callers that pass only `image` silently render the empty "Image coming soon" frame for all 30 photographed products. `MasonryItem`, `FamilyShowcase` and `FeaturedFamilies` pass `src` correctly; **`ProductGallery` and `RelatedProducts` do not**, and `[category]/[slug]/page.tsx` never forwards `product.image` into `ProductGalleryTabs`. Net effect: `/products/architecture` shows 16 photos, `/products/architecture/dhwajadand` shows **zero**. Fix = thread `src` down that chain. (`MegaMenu`/`CraftStory`/`HomeHero` pass only `image` deliberately — they have no local photo.)
- **Cinematic intro**: `DoorScroll` (home, first section, every visit) is a **scroll-scrubbed frame sequence**: an AI-rendered door-opening film (Seedance, animated from the client's temple-gate render with mirrored handles — master at `/public/door/door-open.mp4`) baked to WebP frames (`/public/door/seq/{1600,800}/f-###.webp`, **30fps → 241 frames**; `FRAME_COUNT` in the component must match) drawn on a pinned canvas driven by ScrollTrigger scrub — the visitor's scroll IS the playhead, bidirectional. Overlay states (invitation line, cue, bloom, cream flood) are pure functions of progress via `gsap.set` — do NOT convert them to scrubbed tweens (captured-start-value bugs under StrictMode; see git history). Fires `pm:doors-open` once at 85% so `CinematicHero`'s held intro is mid-flight at arrival; the section ends on the hero's exact cream so the unpin is seamless. To change the film: regenerate via AI video from a corrected keyframe, re-extract frames with ffmpeg (`fps=30`, same names), update `FRAME_COUNT`. (The master mp4 is 8.042s @ 24fps / 193 frames; the sequence is resampled to 30fps, hence 241. Extracting at `fps=20` would yield 161 frames and a film that scrubs 50% too slowly.) Only `door-open-poster.jpg` is loaded at runtime — `door-open.mp4` (9.4 MB) is the archival master, and `door-left/right.webp`, `facade.webp`, `interior.webp` are leftovers from the pre-`DoorScroll` implementation; nothing in `src` references them. Do NOT rebuild as live DOM/WebGL or `<video>` currentTime-seeking (janks). `CinematicHero` self-draws the logo; its scroll-hurry listeners arm only after the door handoff.
- **Kalash showcase is a BAKED 48-frame sprite spin** (`/public/kalash/kalash-spin.webp`, drag-to-rotate, no three.js on home). Client-approved after three failed WebGL photo-projection attempts — do NOT go back to runtime 3D for single-photo products; re-render frames offline instead (simulator technique in git history `778c82a`). GLB products still use the lazy R3F path.
- **NO maroon/oxblood anywhere** — client rejected it; the `--color-oxblood` token is deleted. Velvet sections use the deep-olive family (#4A4428→#2E2313) with pista #DCCF95 / gold #E2CA82 accents. Dark warm heading text uses `--color-heading-brown` #431716 (a brown, not maroon).
- **Fonts are design-synced to the client deck (`../27June.pdf`)**: display/headings = **Spectral** (`--font-display`), italic accent = **Cormorant Garamond** (`--font-serif`), body = Inter. The deck's true fonts (Storica/Juana) are commercial + only exist as incomplete PDF subsets; `src/styles/fonts.ts` documents dropping them in via `next/font/local` later. Don't reintroduce Poppins/Playfair.
- **Brand ornament kit** (`src/components/ui/`, traced to the deck, all `currentColor`-tintable): `ArchMark`, `LotusFlourish`, `OrnamentDivider` (hairline·✦·arch-A medallion·✦·hairline), `SectionHeading` (title + divider — the deck's universal section-header), `VariantChip` (metal coin per material), `SemicircleField` (big olive half-circle, p07), `StatBlock`, `BrandDamask` (tiling pattern). Use these for any new section rather than inventing ornament. See `DESIGN_SYNC_SPEC.md`.
- **GSAP**: import only from `@/lib/gsap` (plugins registered once). Wrap every scroll animation in `gsap.context` + `gsap.matchMedia`, respect `prefers-reduced-motion`, and clean up on unmount. Use `useIsomorphicLayoutEffect`.
- **ScrollSmoother gotcha**: CSS `position: sticky` does NOT work for elements *inside* `#smooth-content` — use a `ScrollTrigger` pin instead (see `CategoryBrowser` filter rail, `ProductGalleryTabs`). Sticky is fine for the Header (it's outside the smooth-wrapper).
- Local catalog data: `src/lib/catalog.ts` (50 products, families, variants) — the fallback/seed until Sanity.

## Build state (code-complete)
The whole build plan is implemented and `next build` is green (66 pages):
- Scroll-UI §0–§9: ScrollSmoother, AssetFrame, masonry (batch reveal + FLIP filter), full product IA (`/products` pinned horizontal → family page → detail w/ material tabs), home (pinned/scrub hero, mask reveals, velocity marquee, magnetic CTA), content pages, polish (cursor, loading, page transitions).
- **Sanity (Prompt B)**: schemas + `lib/sanity/*` + `lib/data.ts` (async, Sanity→catalog fallback); embedded Studio at `/studio`. NOTE the layout split — `app/(site)/layout.tsx` carries the chrome so `/studio` renders clean on the minimal root layout. The Studio page is a **client** component (sanity's `import useSWR from "swr"` breaks under Turbopack's react-server condition otherwise).
- **3D (Prompt G)**: `ProductViewer3D` — R3F, lazy in-view, procedural brass kalash or GLB from `product.model3d`.
- **Resend (Prompt H)**: `/api/contact` (zod-validated, env-gated) + RHF/zod `ContactForm`.

Everything is env-gated with a catalog/mailto fallback, so it runs today with zero credentials.

## To go live (credentials + content only — no code)
- Set env (see `.env.example`): `NEXT_PUBLIC_SANITY_PROJECT_ID` (+ dataset) turns on live content + `/studio`; `RESEND_API_KEY` turns on contact-form email.
- Enter products + upload `heroImage`/galleries in Sanity — frames fill in automatically (`resolveSanityUrl` → `urlFor`).
- Upload `.glb` to `product.model3d` for real 3D (procedural kalash until then).
- Logo SVG from client (deck monogram can be traced as a fallback).

# Paramount — project guide

Premium catalog site for **A Paramount Engineering Works** (Jain/Hindu temple artifacts, est. 1968). View-only, cinematic scroll. Planning docs live one level up: `../PARAMOUNT_BUILD_PLAN.md`, `../PARAMOUNT_CONTENT.md` (locked content + design tokens = source of truth), `../PARAMOUNT_SCROLL_UI_PROMPT.md` (animation layer).

## Conventions
- **Design tokens** live in `src/app/globals.css` `@theme` (Tailwind v4, CSS-first) — palette is olive-brass `#8A7F4A` on cream `#FEF4DA`. Edit tokens there, not in `tailwind.config.ts`. Utilities: `bg-cream`, `text-olive-deep`, `font-display` (Storica), `font-body` (Inter — also the only italic), `rounded-card`. There is no `font-serif`.
- **Type scale** — one restrained, Cartier-disciplined ramp of `pm-*` classes in `globals.css` (UNLAYERED plain CSS, so they always emit and beat the size utilities they replaced — do NOT wrap them in `@layer`, Tailwind v4 tree-shook them there). They set size/leading/tracking/case ONLY, never font-family, so each element keeps its Storica/Inter face. Use these, don't hand-pick `text-[Npx]`: `pm-display`/`pm-display-lg` (hero/page H1, 60/72px), `pm-h2` (section title 40px), `pm-h3` (card/sub title 20px), `pm-lead`/`pm-body`/`pm-small` (18/16/14px prose — pair `pm-measure` to cap the column), `pm-eyebrow` (section kicker 12px caps 0.28em), `pm-label` (UI/chip/caption caps 12px 0.16em), `pm-micro` (tiny caps 10px). A heading is always a heading's size now. `AssetFrame` cover images slow-zoom on hover (~0.7s, clipped by the frame) — the Cartier image reveal; `contain` product floats never move.
- **Every image renders through `AssetFrame`** (`src/components/ui/AssetFrame.tsx`). 30 of 50 products carry the client's real photos (`catalog.ts` `image` → `/public/products/*.webp`, shown UNCROPPED via `fit="contain"` — client mandate: never crop product shots). The rest show the empty frame until Sanity/`urlFor()` fills them.
  - `AssetFrame` accepts two sources — `image` (Sanity) and `src` (the local `/public` photo) — resolving `src ?? resolveSanityUrl(image)`. Every gallery caller now threads `src` down (`ProductGallery`, `RelatedProducts`, `ProductGalleryTabs`); the old bug where photographed products rendered the empty "Image coming soon" plate is fixed. (`MegaMenu`/`CraftStory` pass only `image` deliberately — they have no local photo.)
- **Cinematic intro**: the FIRST ACT of `HomeFilm` (`[0, DOOR_END=0.40]` of its one pinned scroll — the old standalone `DoorScroll` component was merged in and deleted) is a **scroll-scrubbed frame sequence**: an AI-rendered door-opening film (Kling 2.5 i2v, 1080p 10s, generated from a cropped white-marble Swaminarayan-style temple-gate photo used as the START keyframe — master at `assets/door/door-open.mp4`, start frame at `assets/door/door-start-frame.png` — outside `public/`, so versioned but never deployed) baked to WebP frames (`/public/door/seq/{1600,800}/f-###.webp`, **15fps → 151 frames**; `FRAME_COUNT` in the component must match) drawn on a pinned canvas driven by ScrollTrigger scrub — the visitor's scroll IS the playhead, bidirectional. The film itself carries REAL golden sunrays bursting through the parting doors and ends on a full-frame sunburst with **no interior ever revealed** (client dropped an interior-courtyard take) and **no invented door hardware** (two earlier takes hallucinated extra handles; the fix that finally held was BOTH prompt-side — an "ABSOLUTE RULE — THE DOORS HAVE NO HANDLES" block — and data-side: the start keyframe at `assets/door/door-start-frame.png` had its three seam latch cylinders ERASED with a PIL clone-patch, denying the model its anchor. Audit tight seam crops at native res across several timestamps whenever regenerating). After `D.filmEnd` (0.78 in dp-space) the door's tail is the light passage — featureless veils (`.hf-dbloom` soft radial to full, then `.hf-dflood` cream) over the held sunburst frame, handing to the interior. There IS now a **live canvas god-ray layer** (`HomeFilm`'s `raysCv` inside `.hf-zoom`, additive soft irregular beams from the sunburst at 50%/44%, strength scroll-driven via `rayStrength`, shimmer time-driven) — the client asked for "real natural godlike rays falling outside the doors" and this is it; it is fine and intended. The diamond-lattice failure was specifically a **CSS `repeating-conic-gradient` crossing-gradient** (`.ds-rays`) — do NOT reintroduce THAT; discrete canvas beams are the correct approach. No text over the doors, only the bottom scroll cue. Overlay states (invitation line, cue, bloom, cream flood) are pure functions of progress via `gsap.set` — do NOT convert them to scrubbed tweens (captured-start-value bugs under StrictMode; see git history). Fires `pm:doors-open` once at 85% so `CinematicHero`'s held intro is mid-flight at arrival; the section ends on the hero's exact cream so the unpin is seamless. To change the film: regenerate via AI image-to-video from a corrected keyframe, re-extract with ffmpeg (`fps=15`, `scale=W:-2:flags=lanczos`, `-c:v libwebp -q:v 78/72`, `-start_number 0`, same `f-###` names), update `FRAME_COUNT`. (The master mp4 is 10.04s @ 24fps / 241 native frames; sampled to 15fps → 151 frames. This marble scene is detail-dense, so frame COUNT — not webp quality — drives the download; trim frames rather than lower quality, which would blur the carvings. A static ffmpeg build is not preinstalled — fetch one, e.g. evermeet.cx.) Only `door-open-poster.jpg` and the frame sequence are loaded at runtime. The pre-`DoorScroll` leftovers (`door-left/right.webp`, `facade.webp`, `interior.webp`) are deleted; the archival master lives at `assets/door/door-open.mp4`. Do NOT rebuild as live DOM/WebGL or `<video>` currentTime-seeking (janks). `CinematicHero` self-draws the logo; its scroll-hurry listeners arm only after the door handoff.
- **The whole home opening is ONE component, `HomeFilm`, ONE pinned ScrollTrigger, ONE global progress P 0→1 — SCROLL IS THE ONLY PLAYHEAD.** It used to be TWO stacked pinned sections (`DoorScroll` then `CinematicHero`, both now DELETED); the unpin→repin boundary plus a blank-cream gap read as "breaky / three different animations" (client), so they were MERGED. Split at `DOOR_END = 0.40`: door film in `[0, 0.40]` (door-local `dp = P/DOOR_END`), interior/brand/works in `[0.40, 1]` (hero-local `hp`). The film: doors part with live god-rays → geometric push through the opening → warm bloom → cream flood (which IS the exact cream the interior opens on, so the join is invisible — verified: the only dark layer `.hf-dvignette` is 0 across the whole seam window) → the colonnade (`.hv-corridor`) resolves out of that cream → the **"The doors everyone has been opening since 1968."** line (`.hv-line`) breathes in and dissolves → the camera LIFTS to the carved dome (`.hv-dome`) → the brand resolves (mark→wordmark→divider→tagline) → the brand dissolves and "Our Works" (`.hv-works`, `FeaturedGallery`) lands on the SAME dome. Indoors for all of it ("strictly", client). Door sub-beats live in `D` (dp-space), interior/brand/works beats in `H` (hp-space); the header returns at `GLOBAL_BRAND_DONE = DOOR_END + (1-DOOR_END)*H.brandDone`. Dev-only `window.__pmFilm = { apply, DOOR_END, H, D }` (stripped in prod) lets the whole film be seeked and MEASURED without driving scroll. Verified: pure function of P (random-order replay maxDiff 0), no seam flash, header held whole film.
  - **Do NOT drive the hero on a timer.** An earlier cut auto-played acts 2–3 as a GSAP timeline while the doors above were scroll-scrubbed; the client rejected it immediately ("no consistency… maintain continuous scroll") because the film stopped tracking the hand halfway through. `CinematicHero` now uses the SAME machinery as `DoorScroll`: every state is a pure function of scroll progress written with `gsap.set` inside `apply(p)` (no tweens, no captured start values — scrub back and it restores exactly, the StrictMode bug the door already learned); the drawn progress eases toward the scroll target on its own rAF loop with the door's IDENTICAL `TAU_MS = 165` (keep these two in sync — that constant is what gives both acts the same weight); and the same dual pin strategy (GSAP pin on mouse since ScrollSmoother transforms `#smooth-content`; native `position: sticky` on touch where a GSAP pin is jittery). Beats live in `P` (`interiorIn`/`lineIn`/`lineOut`/`lift`/`bloomIn`/`markIn`/…/`brandDone`). Verified by measurement: 51 progress values replayed in two different random orders give `maxDiff = 0`, and the line/logo are never co-visible.
  - **The HEADER is withheld for the whole film** and returns only once the brand is fully resolved (`P.brandDone`, currently 0.69 — read the constant, don't trust this number). Two sections need to hide the same bar across a seam, so the hold is a SET (`src/lib/cinema.ts` → `holdHeader(key, on)`, class `html.pm-intro`): if DoorScroll simply removed the class when its trigger went inactive, the bar would flash in for a frame at the door→interior seam. Never toggle `pm-intro` directly — go through `holdHeader`.
  - The interior opens on the door's EXACT cream (`.hf-dflood`) with `.hv-interior` at opacity 0, so the flood→temple seam is invisible. BOTH interior plates are `priority` — the dome left lazy only fetches when it scrolls into view, so the camera would lift onto a blank plate. The dev-only handle is `window.__pmFilm = { apply, DOOR_END, H, D }` (stripped in production) — `apply(P)` takes GLOBAL progress 0→1; drive it to seek/measure. Verifying the HEADER gate, though, must use REAL scroll, never `apply()`: `apply` calls `holdHeader` as a SIDE EFFECT, so an out-of-order `apply` flips the hold and a naive test reads a state no real visitor reaches (this masked a shipped bug once).
  - **Every beat is EASED, never linear** (`sine.inOut` for cross-dissolves, `power2.out` for copy rising). Three client notes drove the current tuning, so do not "simplify" them back: (a) *"too much blank after the 1st transition"* → the interior now resolves from **p=0** (it used to start at 0.12, so the doors handed over to a long empty cream) and the line is arriving by p≈0.06; (b) *"the 2nd transition isn't smooth"* → the corridor→dome lift is ONE eased value `L` driving BOTH plates (`dome = L`, `corridor = 1 − L`), a mathematically exact matched cross-dissolve — it used to be two LINEAR fades of mismatched length (0.17 vs 0.20), which read as a muddy double-exposure. Measured: `corridor + dome = 1.0000` at every sample through the lift, S-curve slope 9.6× steeper mid than at the ends; (c) *"the 3rd should be better"* → the brand resolves slowly over long overlapping beats. Keep it SLOW — the client has asked for slow-mo three times.
  - **"Our Works" is ACT 4 and lives INSIDE the hero's pinned stage** (`FeaturedGallery`, mounted as `.hv-works`) — it is deliberately NOT a section and has NO background of its own. The brand dissolves as a group (`.hv-brand`), the dome softens to a real 16px blur under a light cream wash (`.hv-wash`), and the work lands on that IDENTICAL ceiling: one backdrop, a content swap. An earlier cut gave it its own copy of the dome behind an opaque frosted panel; the client saw the dome rendered twice and rejected it ("it feels like duplicated bg in both… i want light blurry behind the our works"). **Do not give `FeaturedGallery` a background or a `<section>` again**, and do not re-add a white/cream panel behind it. Because it now rides a 100svh pinned stage, all its vertical sizing is viewport-HEIGHT aware (`clamp(…, Nvh, …)`) — a fixed card height would push the CTA below the fold and make it unreachable (the same class of bug as the /gallery rail). The old **"Four families, one sanctum"** arch-card section (`FeaturedFamilies`) was DELETED at the client's instruction; the families still live on `/products`.
  - `pm:doors-open` / `lib/doors.ts` now has **no subscribers** (the hero no longer needs the handoff — scroll drives it). `DoorScroll` still fires it; harmless, and the wiring is there if a future section wants the cue.
  - **Interior plates**: `/public/interior/{corridor,dome}-{2560,1600}.webp`, 16:9, rendered by Google Nano Banana Pro at 4K FROM the client's own Jain-mandir reference photographs (image references, not invented). 4K masters archived at `assets/interior/mandir-{corridor,dome}-4k.png` — outside `public/`, versioned but never deployed. Cost 300 credits. Do NOT swap these for a generated VIDEO: the only Gemini video model is 720p and ~4x the price, and this marble carving is detail-dense — it would read soft full-screen. The camera move is GSAP, so it stays sharp at any size.
  - **Legibility** (client mandate — the copy must read): the marble is bright and detail-dense, so a warm cream veil (`.hv-veil`) + the divine bloom sit BETWEEN the photo and the type; the marble still reads at the edges so it stays a *room*, not a wash. Brand type is deepened (`olive-deep` / `heading-brown`) to hold contrast over it.
- **Kalash showcase is a BAKED 96-frame photographic turntable** (`KalashOrbit`, frames at `/public/kalash/orbit/{1024,640}/f-###.webp`) — an AI turntable film (Kling 2.5 i2v, start AND end keyframe pinned to the client's `Pakshal kalash` photo so the 360° loop closes seamlessly; loop residual 0.42 vs 8.86 mid-spin) baked offline via `scripts/bake-kalash-orbit.py`, which resamples frames at EQUAL-ROTATION increments (the model eases ~2.6x, so equal-time sampling would feel rubbery). Cartier-grade interaction: 1:1 drag (pointer capture, `touch-pan-y`), release inertia (exponential decay), slow idle auto-rotate that yields to the hand, `role="slider"` + arrow keys, reduced-motion = drag only. NO three.js anywhere now — `Showcase3D` mounts `KalashOrbit` directly, and `ProductViewer3D` (R3F) has been deleted along with `three`/`@react-three/*`, because no route reached it. Reinstate all three to render a real `product.model3d` GLB. Do NOT rebuild any of this as runtime WebGL from a single photo — client-rejected after three failed attempts; regenerate frames offline instead (new film → `bake-kalash-orbit.py` → bump `FRAME_COUNT` if changed).
- **TEXT VOICE is oxblood (client REVERSED the old no-maroon rule, this session).** On the cream ground: ALL heading/big text is `--color-heading-brown` **#4f1a15** (deep oxblood — the token was repurposed from the old #431716), and ALL body/small/caption/eyebrow/label/nav text is `--color-maroon` **#7a2a24** (soft oxblood, legible on cream). Utilities: `text-heading-brown`, `text-maroon` (opacity suffixes work). Olive + gold ACCENTS are untouched — borders, gold hairlines, ornament dividers, SVG-graphic `currentColor` all stay olive/gold; a `text-olive` on an `<svg>` or divider is an accent, not type. Text on DARK velvet panels stays cream/gold/pista (maroon would vanish there). The earlier "NO maroon/oxblood anywhere" note is DEAD — do not restore olive/near-black body text. Velvet panels themselves still use the deep-olive family (#4A4428→#2E2313) with pista/gold accents.
- **Fonts are the REAL brand faces** (client-supplied in `../FONTS`, copied to `src/fonts`, wired via `next/font/local` in `src/styles/fonts.ts`): display/headings/logo = **Storica-Medium** (`--font-display`); body/UI **and every italic** = **Inter** (`--font-body`; the italic is the real `Inter-Italic-Variable.ttf`). There is deliberately **no `--font-serif`** — it used to alias Storica, so `font-serif italic` made the browser fake a slant on a face with `italicAngle 0`. `body { font-synthesis: none }` now forbids any synthesized face; Storica has one Medium cut and cap-height lowercase. Headings are pinned to weight 500, so `font-light` utilities are harmless no-ops rather than faux-thinning. Only **Noto Serif Devanagari** survives beyond these two, and ONLY for Devanagari script (mantra/marquee) — Storica/Inter have no Devanagari glyphs. The brand uses no other fonts — do not add any non-brand Latin face (past regressions swapped in Google web-font stand-ins; keep it Storica + Inter only). The "PARAMOUNT" wordmark is **live text** (`src/components/ui/Wordmark.tsx`), not the old `paramount-word-*.png` (deleted, along with the other unused brand lockup PNGs; only `a-mark-{olive,white}.png` and `deck-damask.webp` ship); the arch-"A" monogram (`a-mark-*.png`) stays an image.
- **Brand ornament kit** (`src/components/ui/`, traced to the deck, all `currentColor`-tintable): `ArchMark`, `LotusFlourish`, `OrnamentDivider` (hairline·✦·arch-A medallion·✦·hairline), `SectionHeading` (title + divider — the deck's universal section-header), `VariantChip` (metal coin per material), `SemicircleField` (big olive half-circle, p07), `StatBlock`, `BrandDamask` (tiling pattern). Use these for any new section rather than inventing ornament. See `DESIGN_SYNC_SPEC.md`.
- **Doors → hero handoff**: `src/lib/doors.ts`. A bare `pm:doors-open` event is not enough — `DoorScroll` renders BEFORE `CinematicHero`, so a reload that restores scroll past the doors fires it during DoorScroll's layout effect, before the hero subscribes, stranding the hero's wordmark at `opacity: 0`. Subscribe with `onDoorsOpen(cb)` (fires immediately if already open), never `addEventListener("pm:doors-open", …, {once:true})`.
- **Coin icons**: the ONLY matcher is `match_icon()` in `scripts/build-galleries.py`. It bakes `VARIANT_ICONS` into `src/lib/galleries.ts`; the client looks labels up there. Don't re-implement it in TypeScript (the old copy had already drifted on "wood" vs "wooden"). After editing the matcher run `MANIFEST_ONLY=1 python3 scripts/build-galleries.py` (no images are touched).
- **Frame sequences**: `DoorScroll` and `KalashOrbit` share `src/lib/frameSequence.ts` (progressive off-thread decode, coarse-to-fine strides, nearest-decoded fallback). Pass `wrap: true` for a loop (turntable), `false` for a film (the door). Don't re-implement it a third time.
- **GSAP**: import only from `@/lib/gsap` (plugins registered once). Wrap every scroll animation in `gsap.context` + `gsap.matchMedia`, respect `prefers-reduced-motion`, and clean up on unmount. Use `useIsomorphicLayoutEffect`.
- **Header** is a full-width frosted **cream** bar (`bg-cream/90 backdrop-blur-md`, olive type) matching the hero ground, with a hairline olive rule under it — outside `#smooth-content`. Brand lockup (arch-A monogram + Wordmark) sits LEFT; the MegaMenu nav + solid Enquire sit RIGHT (the site's original arrangement). Its `--pm-bar-bottom` custom property (4rem — the bar is a `top-0` h-16 sticky, no top padding) is the single source of truth for where the bar ends; the MegaMenu panel and the MobileNav sheet are `fixed` and offset from it (they used to hard-code disagreeing `top-[64px]`/`top-[75px]`). Nav links are `olive-deep`, hover deepens + draws an olive underline. Desktop nav shows at `lg:`, the hamburger below it. `html.pm-intro .pm-header` lifts the bar away while the temple doors own the screen, so Header MUST keep class `pm-header`.
- **ScrollSmoother gotcha**: CSS `position: sticky` does NOT work for elements *inside* `#smooth-content` — use a `ScrollTrigger` pin instead (see `CategoryBrowser` filter rail, `ProductGalleryTabs`). Sticky is fine for the Header (it's outside the smooth-wrapper).
- Local catalog data: `src/lib/catalog.ts` (50 products, families, variants) — the fallback/seed until Sanity.

## Build state (code-complete)
The whole build plan is implemented and `next build` is green (66 pages):
- Scroll-UI §0–§9: ScrollSmoother, AssetFrame, masonry (batch reveal + FLIP filter), full product IA (`/products` pinned horizontal → family page → detail w/ material tabs), home (pinned/scrub hero, mask reveals, magnetic CTA), content pages, polish (cursor, loading).
- **Sanity (Prompt B)**: schemas + `lib/sanity/*` + `lib/data.ts` (async, Sanity→catalog fallback); embedded Studio at `/studio`. NOTE the layout split — `app/(site)/layout.tsx` carries the chrome so `/studio` renders clean on the minimal root layout. The Studio page is a **client** component (sanity's `import useSWR from "swr"` breaks under Turbopack's react-server condition otherwise).
- **3D**: none at runtime. `Showcase3D` → `KalashOrbit` (baked frames). The R3F viewer was removed as dead code; `product.model3d` is currently unrendered.
- **Resend (Prompt H)**: `/api/contact` (zod-validated, env-gated) + RHF/zod `ContactForm`.

Everything is env-gated with a catalog/mailto fallback, so it runs today with zero credentials.

## To go live (credentials + content only — no code)
- Set env (see `.env.example`): `NEXT_PUBLIC_SANITY_PROJECT_ID` (+ dataset) turns on live content + `/studio`; `RESEND_API_KEY` turns on contact-form email.
- Enter products + upload `heroImage`/galleries in Sanity — frames fill in automatically (`resolveSanityUrl` → `urlFor`).
- `product.model3d` has no viewer since the R3F one was deleted; restore `ProductViewer3D` (git history) + `three`/`@react-three/*` to use `.glb` files.
- Logo SVG from client (deck monogram can be traced as a fallback).
